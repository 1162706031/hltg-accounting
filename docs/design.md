## 1. 项目概述

### 1.1 业务背景

公司 "汇隆特钢" 是一家特钢冶炼加工企业：
- **自有冶炼设备**，负责将废料/合金熔炼成钢锭/母棒
- **外协工序**：锻打、电渣重熔、车光、退火 发到外协厂加工
- **业务类型**：11 类明细账（已标准化为 Excel 模板）
- **数据规模**：152 个 Excel 文件，约 10MB，按客户/供应商分目录

### 1.2 系统目标

将 11 类 Excel 手工台账 → 一套 Web 管理系统：
- **录入**：替代 Excel 手工填表，支持批次管理和多行明细
- **查询**：按客户/钢种/日期/批次多维度检索
- **对账**：实时计算往来余额，无需手动维护余额列
- **导出**：一键导出为原始 Excel 模板格式（用于对外对账）
- **库存**：成品/半成品/合金库存自动计算

## 2. 用户权限与审核系统

### 2.1 角色定义

| 角色 | 权限 |
|------|------|
| **admin** 管理员 | 全部权限：CRUD + 审核 + 用户管理 + 字典管理 |
| **accountant** 会计 | 录入/编辑/删除自己创建的订单、录入收付款、库存管理 |
| **reviewer** 审核员 | 查看所有订单、审核(通过/驳回)、不能修改数据 |
| **viewer** 只读 | 仅查看已审核数据、导出报表 |

### 2.2 订单状态机

订单有两个维度: **审核状态** + **工作状态**，合并在一个 status 字段中：

```
  ┌──────┐   提交审核   ┌──────────────┐   审核通过   ┌──────────┐
  │ draft │ ─────────→ │ pending_review │ ─────────→ │ approved │
  └──────┘             └──────────────┘             └──────────┘
       ↑                      │                          │
       │      撤回/重新编辑    │     审核驳回              │ 开始加工
       └──────────────────────┘                          │
       ↑                    ┌──────────┐                 ▼
       └────────────────────│ rejected │←───────  ┌─────────────┐
             重新编辑        └──────────┘          │ in_progress │
                                                   └─────────────┘
                                                          │ 完工
                                                          ▼
                                                   ┌─────────────┐
                                                   │  completed  │
                                                   └─────────────┘
```

**6 个状态说明**:

| 状态 | 含义 | 谁操作 | 可编辑 |
|------|------|--------|:------:|
| `draft` | 草稿 | 录入人 | ✅ |
| `pending_review` | 待审核 | 审核员 | ❌ |
| `approved` | 已审核 (待加工) | — | ❌ |
| `in_progress` | 进行中 | 录入人 | ❌(仅可改状态) |
| `completed` | 已完成 | 录入人 | ❌(仅可改状态) |
| `rejected` | 已驳回 | 录入人(修改重提) | ✅ |

**规则**:
1. 新建订单默认 `draft`
2. 录入人「提交审核」→ `pending_review`
3. 审核员「通过」→ `approved`
4. 审核员「驳回」→ `rejected`（需填写原因）
5. `rejected` 订单→ 录入人修改后重新提交
6. `approved` 订单→ 录入人标记「开始加工」→ `in_progress`
7. `in_progress` 订单→ 录入人标记「完工」→ `completed`
8. 只有 `status IN ('approved','in_progress','completed')` 参与余额计算
9. `approved`/`in_progress`/`completed` 订单不可修改（需管理员「反审核」→ `draft`）

### 3.1b `item` 表设计

> **核心设计**: `steel_grade` 和 `material` 统一为 `item` 表，`item_type` 字段区分类型。旧表已在 schema.sql 中注释废弃，新代码统一使用 `item`。

```sql
CREATE TABLE item (
    id          BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name        VARCHAR(100)  NOT NULL COMMENT '物品名称 — H13, 钼铁60%, 2Cr14Ni ...',
    item_type   ENUM('steel_grade','raw_material','alloy','finished_product','semi_finished','scrap')
                NOT NULL COMMENT '物品类型',
    spec        VARCHAR(100)  DEFAULT '' COMMENT '规格 — 630, 板子, 60% ...',
    default_unit ENUM('ton','kg') DEFAULT 'ton' COMMENT '默认单位',
    is_active   BOOLEAN       DEFAULT TRUE COMMENT '是否启用',
    notes       TEXT          DEFAULT NULL COMMENT '备注',
    created_at  DATETIME      DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME      DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    UNIQUE KEY uk_name_type_spec (name, item_type, spec),
    INDEX idx_type (item_type),
    INDEX idx_active (is_active),
    INDEX idx_name (name)
) ENGINE=InnoDB COMMENT='统一物品字典：钢种/原料/合金/成品/半成品/废料';
```

**物品类型说明**:

| item_type | 含义 | 默认单位 | 示例 | 用于 |
|-----------|------|:------:|------|------|
| `steel_grade` | 钢种 | 吨 | H13, DC53, CrWMn, 1.2888 | 冶炼来料/出钢、外协发出/回厂、销售 |
| `raw_material` | 原材料 | 吨 | 废钢, 废料块 | 冶炼投料、采购 |
| `alloy` | 合金/辅料 | kg | 钼铁60%, 低铬, 高锰65% | 冶炼补加合金、采购、库存 |
| `finished_product` | 成品 | 吨 | 2Cr14Ni板子, H13剥皮元 | 库存 |
| `semi_finished` | 半成品 | 吨 | H13母棒(630) | 库存、外协 |
| `scrap` | 废料 | 吨 | 切头, 锯末 | 库存 |

**7 张表引用 item**:

```
item ──1:N── smelting_inbound       (item_type: steel_grade)
     ──1:N── alloy_addition         (item_type: alloy)
     ──1:N── processing_outbound    (item_type: steel_grade)
     ──1:N── processing_inbound     (item_type: steel_grade)
     ──1:N── procurement_order      (item_type: raw_material, alloy)
     ──1:N── sales_order            (item_type: steel_grade)
     ──1:N── inventory              (item_type: all)

全部通过 `item_id BIGINT UNSIGNED ... FOREIGN KEY REFERENCES item(id)` 关联。

> **inventory 不存储 `item_type`**：inventory 表只存 `item_id`，物品类型通过 JOIN `item.item_type` 读取。在物品管理中修改类型 → 库存自动同步。

### 4.0b 批次号自动生成规则

> 所有订单的批次号由后端自动生成，前端不可编辑。格式为「业务前缀 + 6 位自增序号」，按业务类型独立编号。

| 业务类型 | 前缀 | 格式 | 示例 | 说明 |
|---------|:---:|------|------|------|
| 外协锻造 | `2` | 2 + 6位序号 | 2000001 | 锻造加工 |
| 冶炼加工 | `3` | 3 + 6位序号 | 3000001 | 外来冶炼 + 本厂冶炼共用 |
| 外协电渣 | `4` | 4 + 6位序号 | 4000001 | 电渣重熔 |
| 外协车光 | `5` | 5 + 6位序号 | 5000001 | 车光加工 |
| 外协退火 | `T` | T + 4位序号 | T0001 | 退火加工 |
| 采购 | `P` | P + 4位序号 | P0001 | 原材料/合金采购 |
| 销售 | `S` | S + 4位序号 | S0001 | 产品销售 |

**生成逻辑** (后端):
```python
def generate_batch_no(prefix: str, digits: int) -> str:
    # 查询该前缀下最大序号 + 1
    max_no = db.query(
        "SELECT MAX(CAST(SUBSTRING(batch_no, 2) AS UNSIGNED)) FROM orders WHERE batch_no LIKE :pfx",
        {"pfx": f"{prefix}%"}
    )
    next_no = (max_no or 0) + 1
    return f"{prefix}{next_no:0{digits}d}"
```

**约束**:
- 批次号新建时自动填入，不可手动修改
- 删除订单不会回收批次号（避免跳号）
- 7 种业务类型独立编号，互不影响

**计算逻辑**:
- 成锭率：**自动计算** = 出钢总重 / 投料总重 × 100%（可手动覆盖）
- 来料总价 = ∑(来料用量 × 来料单价)，**单价为空的行自动跳过**
- 合金总价 = ∑(合金用量 × 合金单价)，同上
- 出钢总价 = ∑(出钢重量 × 出钢单价)，同上
- 加工金额 = 出钢总重 × 加工单价（加工单价必填时计算）
- **小计 = 来料总价 + 合金总价 + 出钢总价 + 加工金额**（只汇总有价格的项目）
- 税额 = 小计 × 税率%（税率默认 13，可手动调整）
- 合计(含税) = 小计 + 税额
- ⚠️ 收付款/发票 **不在此页面**，统一在「用户对账」管理

**关键交互**:
- 物品有三种生命周期状态，决定删除行为：

| 场景 | 库存 | 订单 | 操作 | 结果 |
|------|:---:|:---:|------|------|
| 从未使用 | ❌ | ❌ | 可物理删除 | 从 item 表移除 |
| 仅历史引用 | ✅ | ❌ (已完成/已审核) | **停用** | `is_active=false`，历史记录保留 |
| 使用中 | ✅ | ✅ (进行中/待审核) | **禁止操作** | 提示"物品正在加工订单中使用，无法删除或停用" |
| 仅在仓库 | ✅ | ❌ | 需先清空库存 | 提示"请先出库清空该物品的库存后再操作" |

- 停用的物品 → 新建订单/入库时不显示在下拉列表中
- 停用的物品 → 历史订单和库存记录仍可正常查看
- 停用的物品可重新「启用」恢复使用
- 物品名称 + 类型 + 规格 组合唯一（防止重复）

**修改物品的级联影响**:

所有业务表通过 `item_id` FK 关联 item 表，查询时 JOIN 获取名称和类型 → **修改物品名称/类型后，所有引用处自动同步**。

| 引用位置 | 存储方式 | 改名称 | 改类型 | 说明 |
|---------|:---:|:---:|:---:|------|
| 库存列表 | FK → JOIN | ✅ 自动 | ✅ 自动 | 类型筛选/显示自动跟随 |
| 冶炼来料/出钢 | FK → JOIN | ✅ 自动 | ✅ 自动 | 详情页实时反映 |
| 外协发出/回厂 | FK → JOIN | ✅ 自动 | ✅ 自动 | 详情页实时反映 |
| 采购/销售 | FK → JOIN | ✅ 自动 | ✅ 自动 | 列表和详情同步 |
| 仓库选择器 Modal | FK → JOIN | ✅ 自动 | ✅ 自动 | 下拉列表实时反映 |
| 用户对账单 | **存文字快照** | ❌ 不改 | ❌ 不改 | 对账单是历史凭证，保留原样 |
| 库存变动日志 | FK → JOIN | ✅ 自动 | ✅ 自动 | 日志查询时动态关联 |

> ⚠️ **对账单例外**: `party_reconciliation.steel_grade` 是 VARCHAR 文字快照而非 FK。因为对账单是发给客户的正式凭证，必须保留当时的原始记录，不应随物品改名而变动。

> ⚠️ **进行中订单**: 修改物品类型不会影响已在进行中的订单逻辑。例如把 H13 从「半成品」改成「成品」→ 已审核的冶炼订单中该物品显示为「成品」，但订单本身的业务逻辑（外来/本厂入库归属）不受影响。

**后端校验** (DELETE/PUT 接口):
```python
def check_item_usage(item_id):
    # 检查进行中的冶炼订单
    active_smelting = db.query("""
        SELECT COUNT(*) FROM smelting_inbound si
        JOIN smelting_order so ON so.id = si.order_id
        WHERE si.item_id = :id AND so.status IN ('draft','pending_review','approved','in_progress')
    """)
    # 检查进行中的外协订单
    active_outsource = db.query("""
        SELECT COUNT(*) FROM processing_outbound po
        JOIN outsource_order oo ON oo.id = po.order_id
        WHERE po.item_id = :id AND oo.status IN ('draft','pending_review','approved','in_progress')
    """)
    # 检查库存
    in_inventory = db.query("SELECT COUNT(*) FROM inventory WHERE item_id = :id")
    
    if active_smelting + active_outsource > 0:
        raise HTTPException(409, "物品正在加工订单中使用，无法操作")
    if in_inventory > 0:
        raise HTTPException(409, "物品仍有库存，请先出库清空")
    return True  # 可以安全删除
```

### 4.13 批量删除交互设计

> 所有列表页表格统一支持多选 + 批量删除。

**交互流程**:

1. 表头第一列为 ☐ 全选框，每行首列为 ☐ 行选框
2. 勾选任意行 → 顶部 [批量删除] 按钮启用（未勾选时灰色禁用）
3. 点击 [批量删除] → 弹出确认 Modal:
   ```
   ┌──────────────────────────────────────────┐
   │  确认批量删除                             │
   │  ─────────────────────────────────────── │
   │  已选择 3 条记录，删除后不可恢复。         │
   │                                          │
   │  摘要:                                    │
   │  · 冶炼 #3000001 (富烽, 外来)              │
   │  · 冶炼 #3000002 (富烽, 外来)              │
   │  · 冶炼 #3000005 (本厂, 草稿)              │
   │                                          │
   │  [确认删除]  [取消]                       │
   └──────────────────────────────────────────┘
   ```
4. 确认 → `POST /api/v1/.../batch-delete` → 后端批量删除 → 刷新列表
5. 刷新后清空选中状态

**权限约束**:

| 页面 | 可批量删除的记录 | 不可删除 |
|------|:----------------|:---------|
| 往来单位 | 无关联订单的单位 | 有关联订单的单位 (软删除) |
| 冶炼/外协/采购/销售 | 仅 `draft` 和 `rejected` 状态 | `pending_review`/`approved`/`in_progress`/`completed` |
| 库存 | 无关联订单的库存项 | 已被订单引用的库存项 |
| 用户对账 | 所有行 | — |
| 收付款明细 | 所有行 | — |
| 用户管理 | 非当前登录用户 | 当前登录用户自身 |
| 变动记录 | — (只读，不提供删除) | 全部 |
| 审核中心 | — (仅审核操作，不提供删除) | 全部 |

**后端校验**:
- 即使前端限制了可选项，后端仍做二次校验
- 不可删除的记录 → 跳过并返回 `skipped_ids` + `skipped_reasons`
- 响应格式:
  ```json
  {
    "code": 0,
    "data": {
      "deleted_count": 3,
      "skipped": [
        {"id": 5, "reason": "订单状态为已审核，不可删除"}
      ]
    }
  }
  ```

**全选行为**:
- 表头 ☐ 点击 → 全选当前页所有行
- 翻页后全选状态重置
- 全选 200+ 条时 → 确认提示 "将删除 200 条记录，是否继续？"

## 6. 数据流与状态管理

### 6.1 前端状态管理策略

```
全局状态 (Context/Zustand):
  - currentUser          (当前登录用户)
  - sidebarCollapsed     (侧边栏折叠)

服务端状态 (React Query):
  - 所有列表/详情数据使用 useQuery
  - 增删改用 useMutation，成功后 invalidate 相关 query

本地状态 (useState):
  - 表单输入值
  - Modal 开关
  - 表格选中行
```

### 6.2 批次保存数据流

```
用户在详情页修改 →
  点击"保存" →
    PUT /api/v1/smelting-orders/{id}  (完整 JSON body) →
      后端事务:
        BEGIN
        UPDATE smelting_order
        DELETE FROM smelting_inbound WHERE order_id = {id}
        INSERT INTO smelting_inbound (所有当前行)
        DELETE FROM alloy_addition WHERE order_id = {id}
        INSERT INTO alloy_addition (所有当前行)
        COMMIT
    →
  前端 invalidate(['smelting-order', id])
```

**设计理由**: 全量替换比增量 diff 更可靠，避免前端追踪新增/修改/删除行的复杂逻辑。

### 6.3 余额计算数据流

```
任何时候展示余额 →
  前端不存余额值 →
    查询: SUM(amount) - SUM(payment.amount)
    或后端返回: { total_amount, paid_amount, balance }
  →
  收付款增删改后 →
    invalidate 相关 query →
      余额自动刷新
```

### 7.1 成材率 / 成锭率

```python
# 冶炼成锭率
total_feed = SUM(smelting_inbound.weight_ton WHERE side='in')
total_tap  = SUM(smelting_inbound.weight_ton WHERE side='out')
yield_pct  = (total_tap / total_feed * 100) if total_feed > 0 else None

# 外协成材率
total_out = SUM(processing_outbound.weight_ton)
total_in  = SUM(processing_inbound.weight_ton)
yield_rate = total_in / total_out if total_out > 0 else None

### 7.2 往来余额

```python
# 单个订单的余额
balance = order.total_amount - SUM(payment.amount)

# 某个 party 的总余额
total_balance = SUM(所有关联订单的 amount) - SUM(所有关联 payment 的 amount)

# 成品库存

total_alloy_amount = SUM(alloy_addition.weight_kg * alloy_addition.unit_price)

## 7.5 数据一致性规则

> ⚠️ **核心原则**：所有涉及库存、金额、状态变更的操作必须在数据库事务中原子执行。任何一步失败 → 全部回滚。

### 7.5.1 库存一致性

| 规则 | 检查点 | 说明 |
|------|--------|------|
| 扣库不能超量 | 来料/合金/发出 Modal | `本次用量 ≤ 库存余量`，后端二次校验 |
| 入库不能重复 | 出钢/回厂触发 | 同一订单只能入库一次（`completed` 状态设置时检查） |
| 日志不可变 | `inventory_log` 表 | 无 UPDATE/DELETE 权限，只 INSERT |
| 日志必须可追溯 | `ref_type` + `ref_id` | 每条日志关联到具体订单，可反向追踪 |
| 库存扣减与日志同步 | 同一事务 | `UPDATE inventory` + `INSERT inventory_log` 原子执行 |

```sql
-- 反例: 可能出现的脏数据
-- 库存扣了但日志没写 → 库存对不上 → ❌

-- 正确做法: 事务包裹
BEGIN;
  UPDATE inventory SET current_weight = current_weight - :delta WHERE id = :inv_id AND current_weight >= :delta;
  -- 检查 affected_rows = 1，否则库存不足
  INSERT INTO inventory_log (inventory_id, change_type, delta_weight, after_weight, ref_type, ref_id, ...) VALUES (...);
COMMIT;
```

### 7.5.2 订单状态一致性

| 规则 | 说明 |
|------|------|
| 状态只能前进 | `draft → pending_review → approved → in_progress → completed` |
| 驳回是例外 | `pending_review → rejected → draft`（重新编辑后再次提交） |
| 反审核仅 admin | `approved/in_progress/completed → draft`（需 admin 权限） |
| 已审核不可编辑 | `approved/in_progress/completed` 状态禁止修改业务字段 |
| 库存联动在状态变更时触发 | `approved` 时扣库存（发出/来料），`completed` 时入库存（出钢/回厂） |

```
状态变更 → 库存联动对照:
  draft → pending_review    无库存影响
  pending_review → approved 扣: 来料(原料)/发出(本厂成品)/合金(本厂)
  approved → in_progress    无库存影响
  in_progress → completed   入: 出钢(成品/半成品)/回厂(本厂)
  any → draft (反审核)      回滚: 恢复已扣库存 + 移除已入库存 (admin 慎用)
```

### 7.5.3 金额一致性

| 规则 | 说明 |
|------|------|
| 收付款 ≤ 订单金额 | `SUM(payment.amount) ≤ order.total_amount` |
| 发票金额 ≤ 订单金额 | `SUM(invoice.amount) ≤ order.total_amount` |
| 余额实时计算 | 不存储余额字段，每次查询 `amount - SUM(payment)` |
| 对账行余额 | `debit - credit - payment_amount` = 该行剩余未结算金额 |

### 7.5.4 删除/停用约束

| 操作对象 | 约束条件 | 拒绝提示 |
|---------|---------|---------|
| 删除物品 | 无进行中订单引用 + 无库存 | "物品仍在加工/库存中使用" |
| 删除往来单位 | 无进行中订单 + 无未结算余额 | "该单位仍有未结清往来款项" |
| 删除订单 | 仅 `draft`/`rejected` 状态 | "已审核/进行中/已完成订单不可删除" |
| 删除库存项 | 未被进行中订单引用 | "该库存项正在被订单使用" |
| 修改物品名称/类型 | 任何状态均可 | 通过 FK JOIN 自动级联到所有引用处（对账单快照除外） |

### 7.5.5 并发控制

| 场景 | 方案 |
|------|------|
| 同一库存被两人同时扣减 | `SELECT ... FOR UPDATE` 行锁 |
| 同一订单被两人同时编辑 | 乐观锁 `version` 字段 或 悲观锁 |
| 批次号生成 | 数据库序列 / `SELECT MAX + 1` 在事务内执行 |

### 7.5.6 数据校验清单

部署前和上线后定期执行：

```sql
-- 1. 库存日志与当前库存对账
SELECT inv.id, inv.current_weight,
       (SELECT SUM(delta_weight) FROM inventory_log WHERE inventory_id = inv.id) AS log_sum
FROM inventory inv
HAVING inv.current_weight != log_sum;

-- 2. 订单金额与收付款对账
SELECT so.id, so.total_amount,
       (SELECT SUM(amount) FROM payment WHERE ref_type='smelting_order' AND ref_id=so.id) AS paid
FROM smelting_order so
HAVING paid > so.total_amount;

-- 3. 孤儿 item 引用检查
SELECT si.id FROM smelting_inbound si LEFT JOIN item i ON i.id = si.item_id WHERE i.id IS NULL;

-- 4. 负库存检查
SELECT * FROM inventory WHERE current_weight < 0 OR current_pieces < 0;
```

## 附录 D: 移动端扩展规划 (优先级: 最低 — 远期)

> **状态**: 预留设计，不在当前开发范围内。Web 端完成后再评估。

### D.1 定位

移动端定位为**辅助操作端**，非全功能替代。主要覆盖：

| 功能 | 说明 |
|------|------|
| 库存速查 | 扫码/搜索查库存、归属、数量 |
| 快速入库/出库 | 到货入库、发货出库，拍照留证 |
| 审核通知+操作 | 推送待审核提醒，直接通过/驳回 |
| 仪表盘 | 关键数字卡片（应收/应付/库存） |
| 批次追踪 | 扫批次号查看订单进度 |

**不在移动端做**：复杂子表编辑（冶炼/外协详情页）、Excel 导出、系统设置。

### D.2 技术方案

| 维度 | 方案 A: PWA | 方案 B: React Native | 推荐 |
|------|-----------|---------------------|:---:|
| 开发成本 | 低（复用 Web 代码） | 中（独立开发） | |
| 离线能力 | ✅ Service Worker | ✅ 本地存储 | |
| 原生体验 | 一般 | 好 | |
| 推送通知 | Web Push (iOS 受限) | ✅ 原生推送 | |
| 扫码 | ✅ 浏览器 API | ✅ 原生相机 | |
| 拍照 | ✅ 浏览器 API | ✅ 原生相机 | |
| **推荐** | **先做 PWA** | 有预算再升级 | ✅ |

**建议路径**: PWA 先行 → 验证需求 → 必要时 React Native 重写。

### D.3 API 兼容

当前后端已是 RESTful API，移动端可直接复用，无需额外开发。移动端需要时新增：

| API | 说明 |
|-----|------|
| `GET /inventory/scan?qrcode=xxx` | 扫码查库存 |
| `POST /inventory/quick-in` | 快速入库（简化版） |
| `POST /inventory/quick-out` | 快速出库（简化版） |
